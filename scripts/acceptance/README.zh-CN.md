# LocalCode 0.1.15 候选包验收

第一次测试、对环境配置不熟悉，请先看 [先看这里](先看这里.md)。完成基础启动反馈后，再由维护者安排下面的完整验收。

这是发布前测试包。测试未完成前，不代表正式发布或完整验收通过。应用未签名；遇到系统阻止时记录提示并反馈，不需要关闭系统防护。

## 环境与回传

1. 将验收包和候选 ZIP 放在可写的新目录。双击 `Check-Environment.cmd`，保留 `results/environment-*.json`。要求 Windows 11 x64、标准非管理员账号、未预装全局 Node/npm/Git/Python/Ollama。预检不符合时仍可记录兼容性结果，但不能填“干净首次安装通过”；不要卸载已有软件。
2. 对照候选包的 `SHA256SUMS.txt`，用 `Get-FileHash -Algorithm SHA256 -LiteralPath '完整 ZIP 路径'` 核对哈希。把提交和 ZIP 哈希填入 `results-template.json` 的副本。
3. 每项状态填 `PASS`、`FAIL`、`UNRUN` 或 `ENVIRONMENT_MISMATCH`，写清实际步骤、结果、错误和证据文件。只回传结果表、环境报告和脱敏截图；不要回传整个应用数据目录、API Key 或私人项目。
4. 云端真实任务由维护者使用自己的隔离配置完成。这里可以只保存无密钥的云端配置并选择模型来核对 UI；不得将此项写成真实云端推理通过。若自行使用云端服务，只在本机输入自己的凭据。

检查启动器使用系统 Windows PowerShell 5.1，并仅为其子进程传入 `-ExecutionPolicy Bypass`。它不调用 `Set-ExecutionPolicy`，不修改用户／机器策略，也不以管理员身份重启。组织组策略优先级更高；如仍被拦截，回传错误并保留未验收状态，不绕过组织控制。

## 成功路径

- P01：完整解压便携 ZIP，双击 `Start.cmd`，打开设置，保存并选择云端模型。确认无需全局开发工具、Ollama 或管理员权限便能进入桌面。不要在压缩软件内直接启动 EXE。
- S01：单独完整解压源码 ZIP，运行 `Setup.cmd`，选“仅桌面”。完成后启动桌面；本地模型可保持未安装。
- S02：另一个干净目录运行源码 `Setup.cmd`，选“本地模型＋桌面”，使用默认模型。记录运行时版本、安装记录和模型 digest；全新安装不能复用此前的模型缓存来冒充首次下载。建议至少 25 GiB 可用空间；不足则记录，勿清理旧数据来冒险测试。
- F01：分别在如“文档\LocalCode 中文 测试”这样的中文、空格目录重复启动。
- M01：复制 `project` 到新的项目目录。要求模型先读取两个文件，修复加法实现，请求批准后执行 `powershell.exe -NoProfile -File .\Test-Numbers.ps1`，观察 3 项通过并总结。仅得到一句回复不算通过。
- M01 拒绝：新会话要求使用终端创建 `denied.txt`，在批准界面拒绝；文件必须不存在，模型不得自行改换工具创建它。取消：新会话要求经批准执行 `Start-Sleep -Seconds 30` 后再创建 `after-cancel.txt`，批准后立即取消，观察至少 10 秒；后续文件必须不存在。
- M02：保存记录后重启电脑。启动应用，在设置中显式启动本套服务，确认相同模型和配置，再运行一次真实读取／推理任务。不要将仅重启应用填写为重启电脑通过。

## 失败路径

只在候选包的副本和虚构项目中执行，不修改私人目录或全局设置。

- F02：断网后尝试安装，记录提示；恢复网络后从同一目录、以相同选项重试。另测下载进行中中断，再重试；确认恢复成功且无旧数据丢失。
- F03：仅在已有可用的、容量受限的临时测试磁盘中测试空间不足。没有这类环境就填 `UNRUN`，不要填满系统盘。记录提示是否说明缺少空间和处理后的重试位置。
- F04：使用你自己已安装／管理的 Ollama 占用 11434，再在候选包副本中尝试托管安装。应说明端口占用并拒绝；原服务应继续可用。不要停止别人的服务。此项单独环境与首次安装预检分开记录。
- F05：复制一份候选包，在副本中移走 `LocalCode/app/current.txt` 或被指向的 EXE，再启动。应说明缺少文件及完整解压／修复方式。保留原候选包以恢复，不动任何旧安装。

只有必需项目全部有符合条件的证据后，维护者才会解除正式 Release 阻塞。
